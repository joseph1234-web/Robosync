Uno has no built-in Bluetooth or Wi-Fi. It uses the included USB bridge on a laptop. The phone can sync and cache its website Dashboard; direct offline Uno-to-phone Bluetooth needs additional compatible hardware and firmware.

Physical GPIOs are wiring points. V0–V255 are data labels. They do not reprogram the board or prove the wires are connected. The helper validates the selected board’s supported pin subset and generates its matching sensor header.

Pick the sensors you use

  • Potentiometer: required raw input, default V0.
  • Temperature: choose no sensor, DHT11, DHT22 or DS18B20. DS18B20 reports temperature only; the app shows humidity as not enabled.
  • LDR divider: optional raw light input, disabled by default, default V7. Raw counts are not calibrated lux.

Website → existing project → Library: select the matching board’s Pot + DHT + Light or Pot + DS18B20 starter. Preview additions, then Save dashboard. Compatible existing stream/card IDs, history and styles are reused. Conflicting units stop the preview.

For USB, Devices & data → select the existing device → Download sensor USB binding. This public configuration chooses existing typed streams; your password and sign-in tokens are never placed in it or in firmware. The original USB binding remains available for the original starter.

Checked in software

The website, APK and sketches share generated board/pin contracts. All 32 default-pin board/sensor configurations compile with the pinned Arduino toolchain. Host C++ output is decoded by the actual native packet parser, and synthetic peers exercise authentication, legacy fallback, typed queues and upload retries. A reference compiler manifest appears in the firmware review.

Legacy potentiometer, Direct 1.1.1 DHT and Sensors 1.2.0 firmware remain supported by the new APK. Sensors 1.3.0 uses the new capability format and should be paired with Android 1.10.0. Existing private QR setup, enrolled keys, queues, layouts, themes, alerts, classroom and camera tools remain.

These are software checks. No physical sensor, radio, phone lifecycle or scrolling test was performed for this update. Those checks stay deferred at your request.

Same Dashboard, clear sync

ESP32 profiles use the existing phone relay: local readings can continue offline, and Auto-sync retries queued uploads when phone internet returns. Local only keeps website traffic paused until you resume. Choose the phone or USB sender as the upload path for a board.

The USB bridge previews locally without internet; Send mode uses your existing owner account and RLS. It stops on an unconfirmed cloud failure and does not keep a disk upload queue. Uno’s downloaded phone Dashboard remains available offline after Sync.

Board router Wi-Fi supplies a local link. Unattended board-to-cloud upload is conditional in the revised plan and is not enabled by these profiles; the existing phone/laptop upload path handles automatic website delivery. No account password, refresh token or service-role key belongs in firmware.

Robot-car operation remains paused until the motor driver is available. Other board families need their own reviewed profile; selecting a catalog entry alone does not add firmware support.
