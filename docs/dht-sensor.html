01 / UPDATE IN PLACE

Keep your uploaded sketch.

Install Android1.6.0 over the existing app. Do not uninstall or clear its data. Your saved board keys, account and queued potentiometer readings remain.

This update understands the DHT sensor extension in the provided Direct1.1.1 sketch. An app upgrade alone does not require flashing again or resetting the board claim.

02 / USE THE SAME STREAMS

Prepare the Dashboard.

Website → your existing project → Experiments & groups. Select ESP32 Potentiometer + DHT11 / DHT22 and the existing ESP32 device. Choose Review experiment → Continue to Dashboard → Save dashboard.

The review keeps compatible stream IDs and cards, adding only missing ones. A different unit/type stops setup for review. Do not create another ESP32 device for the same board.

03 / CONNECT THE PHONE

Bluetooth + phone internet.

APK → Sync → Devices → Connect device. Choose the existing Potentiometer + DHT target. Reconnect your saved board with Bluetooth, or use your matching private setup QR for first enrollment.

Keep the phone on normal internet Wi-Fi or mobile data. Joining the board's local Wi-Fi does not provide internet. The board's router connection is separate from website upload.

04 / CONFIRM DELIVERY

Choose Auto-sync.

In Sync options, choose Auto-sync · queue and upload when internet returns. The app links the potentiometer and compatible temperature/humidity streams on the selected device using your existing owner account.

Verify actual changing readings on the phone, then Website upload confirmed. Open the normal phone Dashboard; the website refreshes while open. Local only deliberately pauses uploads and retains the queue.

Check the three streams.

ReadingStream / unitPhysical pin
Potentiometerpot_raw · rawGPIO34
Temperaturetemperature · CDHT DATA on GPIO13
Humidityhumidity · %Same DHT DATA on GPIO13

V0, V2 and V6 in your sketch are optional software labels. They do not select physical pins or upload automatically. Keep your current private settings only in RoboSynctUserConfig.h if you edit firmware later; do not duplicate them inside the sketch.

Read the status, then recover.

No local reading: check board power, Bluetooth permission and authenticated connection. Successful Arduino upload alone does not establish a phone connection.

DHT read failed: the app keeps older data stale and sends no fabricated zero. Check GPIO13, the sensor's power/ground/data labels and whether the sketch's DHT11/DHT22 type matches your sensor. A bare four-pin DHT needs its data pull-up; modules may already include one.

Live on phone, waiting for internet: keep collecting in Auto-sync and restore phone internet. Automatic uploads off / Local only: choose Auto-sync deliberately. Owner/stream access denied: sign in to the account that owns the selected existing project, then Retry linking.

Values upload but no cards: bind those same streams to website widgets, Save dashboard and Sync the phone. Existing history is retained.

This release was tested with synthetic encrypted peers and cloud responses. Real sensor/radio/phone acceptance remains pending. Motors remain disabled/deferred. No firmware flash, factory reset, new backend or SQL migration is performed by these steps.
