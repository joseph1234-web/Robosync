One account.
Android + web.

The website includes email registration, Google and Facebook sign-in, SMS verification, and account linking. The app administrator must finish the provider settings below. The native Android development APK is available with encrypted offline dashboards and QR connection. Download the APK and installation guide. The phone uses a selected-project grant; account registration and provider linking remain in this website.

1. Website and email registration

  1. In your Supabase project, open Authentication → URL Configuration. Set Site URL to the current RoboSynct website origin shown in your address bar.
  2. Add that exact origin with a trailing slash to Redirect URLs. When you rename the website URL, update these settings too.
  3. Under Sign In / Providers, enable Email and allow new registrations. Keep email confirmation enabled when you want users to verify their addresses.
  4. Use Create account on RoboSynct. Follow the confirmation email, then sign in with your password. Configure your own SMTP service when email delivery or limits require it.

Email confirmation links return to the sign-in page; the website asks for your password rather than storing tokens from the URL fragment.

2. Google / Gmail

  1. Create a Web application OAuth client in Google Auth Platform.
  2. Add the RoboSynct website origin under Authorized JavaScript origins.
  3. Add this Supabase callback under Authorized redirect URIs:
    https://zxwtofzjnqshrojsvkhn.supabase.co/auth/v1/callback
  4. In Supabase Authentication → Sign In / Providers → Google, enable Google and enter the client ID and secret directly there.
  5. Complete Google's consent/testing settings for the intended users. Return to RoboSynct and choose Refresh sign-in methods, then Google / Gmail.

The website uses an authorization code with PKCE. Complete the redirect in the same browser tab where sign-in began.

3. Facebook

  1. Create a Meta developer app and configure Facebook Login.
  2. Set its Valid OAuth Redirect URI to the same Supabase callback shown above.
  3. Enable Facebook in Supabase Authentication and enter the Facebook app ID and app secret there.
  4. Complete Meta's app settings, permissions, and release requirements for your intended audience, then refresh the methods in RoboSynct.

Google and Facebook secrets belong in Supabase/provider dashboards. Never paste them into this website's source, widget settings, or sensor data.

4. Phone numbers and SMS

  1. Enable Phone in Supabase Authentication and configure a supported SMS provider. Phone sign-in cannot send real SMS without provider setup.
  2. For development without SMS delivery charges, configure Supabase test phone numbers and fixed verification codes. Keep them restricted to testing.
  3. Use the complete country code, such as +639171234567. Choose Send SMS code and enter the received code. The website enforces a wait before resending; Supabase also enforces its rate limits.
  4. For an existing account, sign in first and use Account & Android → Connect a phone number. This verifies the phone against that account.

Real SMS delivery can incur provider charges. A separate phone registration does not automatically merge an existing email account.

5. Keep the same projects across sign-in methods

Open Account & Android while signed in. Connect Google, Facebook, or a phone there. To connect social identities, enable Allow manual linking in Supabase Authentication settings. An identity already owned by another user cannot simply be attached here; the website does not move project ownership between accounts.

The website verifies that a linking callback returns the same Supabase user ID. Your existing owner-only database policies continue to control project access.

6. QR connection for the Android app

  1. If QR setup has not been installed, open qr-pairing.sql, copy the entire file, and run it in this Supabase project's SQL Editor. It adds three RLS-protected pairing tables and a small RPC API. The existing project tables and their grants are kept.
  2. Save a dashboard in RoboSynct. Choose Project → Connect Android → Generate connection QR. A code lasts five minutes.
  3. The app scans the URL directly in its bundled Camera2 / ZXing scanner. Paste a copied connection link if camera permission is declined. The QR holds only an invitation ID and short-lived invitation secret. It does not contain a password, account access/refresh token, or service key.
  4. The phone generates its own 32-byte random device token, requests the connection, and displays a six-digit comparison code. Compare the code on the phone with the browser, check the match box, then select Approve phone.
  5. The phone receives a revocable, project-scoped connection. It can read the saved dashboard and recent bound stream data without signing in as the browser user. Optional permission allows reordering/resizing existing widgets; it cannot add bindings, change rules, or delete projects.
  6. Open Connect Android → Paired phones → Revoke to stop a connection. Grants expire after 30 days. Dashboard layout and data checks run about every five seconds while views are open and online; unsaved browser drafts are retained.

Install the Android development APK on Android 8.0+. It includes native charts, stream statistics, CSV export, event logs, themes, an offline cache, and queued layout changes. Camera/media sources open explicitly; local camera preview stays on the phone and external HTTPS media uses a compatible viewer. A separate browser protocol test remains available by opening a connection link in another tab.

API contract · pairing v1

Call these functions with POST /rest/v1/rpc/<name> at the same Supabase project, using its publishable key in the apikey header and JSON bodies. The APK must use its own device token; it must not copy the website's Auth session. Owner-only methods below use the signed-in browser's user access token.

Caller / functionJSON parameters / purpose
Browser · rs_pairing_createp_project_id, p_request_id, p_invite_token. UUID v4 and 64 lowercase hex characters from 32 random bytes. Retain the same request ID/token when a response is uncertain.
APK · rs_pairing_claimp_request_id, p_invite_token, p_device_token, p_device_label. Generate and securely retain a different 32-byte device token before sending; reuse it for retries. Show the returned match_code.
Browser · rs_pairing_status / rs_pairing_decideStatus uses p_request_id. Decision adds p_code, p_approve, p_allow_arrange. Only the project's owner can approve the matching request.
APK · rs_pairing_resultp_request_id, p_device_token. Poll about every two seconds until approved/denied/expired. After approval, save connection_id, the expiry, and the device token.
APK · rs_mobile_dashboardp_connection_id, p_device_token. Returns the selected project, saved dashboard, up to 100 newest readings per bound stream, up to 50 events, permissions, and refresh time. No account session or device configuration secrets are returned.
APK · rs_mobile_arrangep_connection_id, p_device_token, p_base_revision, p_save_token, p_layout. Layout is an ordered array of {id,columns,height} for every existing widget. Columns 3–12; height 0 or 160–960. Use a stable UUID save token for retries. On DASHBOARD_CHANGED, reload and preserve the local draft.
Browser / APK · disconnectOwner: rs_pairing_revoke(p_connection_id). Phone: rs_mobile_disconnect(p_connection_id,p_device_token). Browser pending invitations can be cancelled through rs_pairing_cancel(p_request_id).

QR format: this website's HTTPS /android-connect.html with fragment fields v=1&request=<uuid>&invite=<64-hex>. The app must validate version, expected website origin/path, and use the Supabase endpoint compiled into the app. Do not use a database endpoint supplied by an unknown QR. The URL fragment is removed by the browser test before API calls.

Protect the device token at rest in the APK using encryption with a key protected by Android Keystore. Send it only in HTTPS RPC request bodies, not URLs, logs, screenshots, or QR codes. The database stores token hashes. See Android Keystore and Supabase functions. Automated checks include a local Postgres runtime, Android offline/sync state tests and a real ZXing QR decode. APK compilation and signatures are verified. Physical phone/emulator, camera, permission prompts and live paired sync still need end-to-end testing.

7. Shared dashboard appearance

Use Theme in the top bar to change the whole website. In Dashboard, choose a named dashboard theme and save it to share that appearance. Each widget can override its dashboard theme in the widget editor. Website preference stays in this browser; Follow website / device inherits the appearance selected on each device.

Saved layouts use widgets.id = project.id, config.kind = dashboard_layout, and schema_version = 3; the website also reads versions 1 and 2. config.theme is site or a named theme. A widget's optional theme overrides it. Names are mint, midnight, ocean, violet, sunrise, contrast. Layout edits retain revision and save-token checks.

The APK maps these theme names to native colors and represents the twelve saved widget types. Its gauge uses a native progress display. The app theme is local to the phone; named dashboard/widget overrides sync. Browser webcam access and local files stay on their own device.

A full account sign-in remains an option for an Android workspace. It uses the same Supabase user and normal RLS. QR grants give access only to the selected dashboard and its permitted actions.

8. Work offline, then sync

  1. Complete QR approval online and wait for the app to report an up-to-date dashboard.
  2. Open the app without internet to view its last cached dashboard, readings, charts and events. The cache is encrypted using Android Keystore and excluded from backups.
  3. If browser approval allowed layout editing, long-press to reorder or tap Arrange to resize. Changes are saved locally; choose Queue changes to send them when online.
  4. Reconnect and choose Sync. Repeated interrupted saves reuse the same operation ID. If the website revision changed, the app preserves the draft and asks you to use the website layout or explicitly reapply your arrangement to the current widgets.

The app uses up to 100 newest readings per bound stream and 50 recent events. Website date filters are separate. One project is paired at a time. Grants expire after 30 days; remote revocation is detected at the next online check. Background work may be delayed by Android battery restrictions. Open the app for an immediate refresh. Original ESP32 BLE/local Wi-Fi is available through the native direct connection; other board transports and full account editing require separate support.

Register a device, then verify its data

Registration saves a device record. It does not pair a physical board or verify its network connection.

  1. Open your project, choose Add device, and select simulation or registered hardware.
  2. Choose a saved device and check its sensor streams. If stream creation failed, use Add stream on that same device; keep its existing ID and history.
  3. For simulation, select Run sensor test. The generated samples are labeled as practice data. Refresh loads saved readings for the selected time range.
  4. For an original ESP32 DevKit V1, use the USB sensor starter: supplied firmware, a local PC preview and an owner-authenticated adapter for the existing Potentiometer raw stream. A physical board test is still required. Matching original ESP32 firmware also supports native BLE/local Wi-Fi; see the current Android connection guide. Registration or a recent timestamp does not confirm a live link.

Recover without losing your project

  • Network unavailable: reconnect, then refresh. Keep the same device and retry an uncertain registration with the same open form.
  • No readings: check the selected stream and history range. Use Refresh; an empty range does not prove a board is disconnected.
  • Stream request failed: select that device again. Reading request failed: use Sensor data → Refresh.
  • Hardware not connected: check the exact board, power, serial port and installed firmware before setup. Do not reset the board or replace Wi-Fi credentials just to register it.
  • Android dashboard pairing: use the existing project QR, compare the six-digit code and approve it in the website. This grants dashboard access; it does not pair a sensor board or enable motor control.

Keep private database passwords and service keys out of firmware, browser forms, QR codes and shared diagnostics.
