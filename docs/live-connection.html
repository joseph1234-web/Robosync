Already connected successfully? Keep your ESP32 sketch and potentiometer wiring. This update is for the APK and website. No new Supabase SQL is required. Original ESP32 with RoboSynct Direct firmware is supported; other Arduino boards need a compatible transport and firmware.

Do this on your Android phone.

  1. Install Android 1.2.0 over the existing app, then confirm your saved Dashboard still opens.
  2. Choose Connect ESP32 / stream setup on Dashboard. Existing Settings access also works.
  3. Select your enrolled board with BLE or its private Wi-Fi IP once. Leave the setup-code field empty when this phone already has its board key. A new board still requires physical BOOT enrollment.
  4. Leave Keep sensor connected after leaving the app enabled. Allow notifications to see its connection status and Stop action.
  5. Choose Choose Dashboard stream / website upload, then your existing ESP32 device and Potentiometer stream. Use Dashboard only · offline for local viewing, or Dashboard + verify upload after owner sign-in.
  6. For website updates, sign in with the existing project owner's RoboSynct account and enable Queue new readings and upload when internet returns once. QR dashboard approval and board enrollment keep their existing permissions.
  7. Return to Dashboard and rotate the knob. Existing value, gauge, chart and history widgets for that stream show new local samples without tapping Sync. Keep the website dashboard open with Auto refresh · 5s enabled to see uploaded readings.

Firmware samples about every five seconds. Website delivery usually adds another refresh interval and network time. Offline samples wait in the encrypted outbox. Dashboard-only viewing does not grant cloud upload permission.

Wi-Fi without repeating setup.

Restore the board's router connection

In the direct screen, choose Send 2.4 GHz Wi-Fi settings. Leave Remember Wi-Fi encrypted on this phone enabled if wanted. After an authenticated reconnect to a restarted board, the app can resend those settings automatically. The existing firmware keeps router credentials in RAM.

Save the board AP on your phone

Choose Show enrolled board's AP details → Save network in Android and approve Android's save dialog once. On Android 8–10, save it in Wi-Fi settings. Android chooses whether and when to join; a local ESP32 AP may have no internet. Keep Bluetooth enabled to let the saved BLE route reconnect.

Reconnect uses an enrolled board key and verifies its board identity. Saved routes retry with increasing delays up to 30 seconds. It does not claim unknown boards or bypass Android's network or Bluetooth permissions.

Check the new behavior.

Connection and Dashboard

  1. Rotate the knob; confirm matching new values and timestamps on APK Dashboard and website.
  2. Press Home, lock the screen, wait a minute, then return. Confirm samples continued and the connection notification remained.
  3. Move out of range or restart the board. Return nearby and confirm reconnect without another setup code.

Offline queue and Stop

  1. Briefly remove internet while retaining BLE; collect readings.
  2. Restore internet. Confirm the queue drains and the website updates automatically.
  3. Use notification Stop connection. Confirm collection stops and stays stopped until you choose Resume saved board.

These new phone sleep, OEM battery, permission and radio tests need your handset. Host protocol/storage/reconnect-safety checks and the signed APK build pass. Earlier phase tests you already accepted remain recorded. A force-stop, Bluetooth off, lost power, lost range or Android battery policy can interrupt collection. No app can guarantee a live radio link in those conditions.

Your working features stay available.

QR account/phone pairing, offline reopening, themes, layouts and conflict handling, stream history and CSV export, USB ingestion, templates/groups, media and Rules preview remain. Local overlays do not overwrite the saved QR snapshot. Cloud uploads append stable sample IDs using the owner's existing RLS permissions; no database migration is included.

Motor hardware remains deferred. Leaving the Drive screen stops/disarms controls immediately. Background collection never re-arms motors or queues movement.
