Update on your Android phone.

  1. Install the new APK over RoboSynct. Sign in with the same existing email/password as the website. The password is not saved. Your account session is encrypted on the phone.
  2. Your existing Dashboard opens automatically when one owned project exists. With several projects, choose the one you want. Prior QR connections remain under Account → Use my existing QR connection.
  3. Open Connect ESP32 / stream setup. Choose Connect with Bluetooth for an enrolled board, or Scan my ESP32 setup QR for the new configured starter.
  4. With one matching existing Potentiometer stream, the account flow maps it automatically. If several streams exist, choose the existing project/device/stream once. Existing widget bindings and IDs remain.
  5. Select Online for automatic website sync. An internet outage queues readings and retries when internet returns. Select Offline to pause cloud requests while Bluetooth/local Wi-Fi keeps feeding the same Dashboard; choose Online to drain the queue.
  6. Leave Keep sensor connected after leaving the app enabled for sensor collection while backgrounded. Its Android notification has Stop connection. Android force-stop, battery policy, radio/power loss and range can interrupt collection.

Bluetooth is the local sensor transport in both online and offline use. It does not provide internet itself. Board Wi-Fi can be saved through Android's one-time network approval. New camera video is foreground-only and separate from the background sensor service.

Configure the sketch once.

Easy ESP32 setup generates a private RoboSynctUserConfig.h and matching setup QR entirely in your browser. Put that header beside the starter sketch, then upload manually in Arduino IDE. Board Wi-Fi credentials and optional router/hotspot settings can be configured in that header. Each board needs its own private configuration.

The QR transfers a strong key, so you do not type the old long PIN. It is not a shared default password. New unclaimed boards offer a five-minute configured setup window; physical BOOT can reopen it. Existing claimed keys and device identity survive a normal firmware update with Erase All Flash disabled.

Protected camera preview on local Wi-Fi.

Your potentiometer ESP32 DevKit V1 has no camera. This camera path needs an actual compatible MJPEG camera and a laptop relay on the same local network. It does not stream video over BLE or store frames in Supabase. Camera board wiring/optics remain unverified until you supply and test actual camera hardware.

  1. Download the protected local relay. Extract it on the laptop. Use Python 3.12+ and install its requirements.
  2. Initialize with the laptop's actual private IPv4 address. The relay creates its own certificate, camera read token and private JSON file. Keep that folder private.
  3. Start it with an actual compatible HTTPS MJPEG camera source. Private-LAN HTTP upstream requires the explicit option described in the relay README. No public upstream URLs or redirects are accepted.
  4. Select the generated private JSON below. Scan the resulting QR in APK → Camera → Scan protected camera QR, then tap Start. The APK verifies the scanned certificate pin before sending the read token.
python -m pip install -r requirements.txt
python camera_relay.py --init --host 192.168.1.8
python camera_relay.py --upstream https://192.168.1.9/stream

Replace both example addresses with actual private addresses. Keep the relay running while viewing. It allows one authenticated viewer, uses TLS 1.2+, limits JPEG frames to 1 MiB, and saves no video. Missing camera, bad source, wrong identity or denied access is shown as unavailable. Snapshots require a separate Save action and file choice.

The selected file is read in this browser only and is not uploaded.

Install Phase 4 backend capabilities separately.

Prepared and tested in staging; not automatically installed in your live Supabase project. Account sign-in, the unified Dashboard, board QR setup and phone-local sensor collection do not require this SQL. Classrooms and database cloud rules stay unavailable until their backend is installed.
  1. Keep your existing verified backup and current project. Review Phase 4 additive setup SQL.
  2. In your existing Supabase project, open SQL Editor and run the complete setup file once. It creates new classroom/cloud-rule objects and one event-only telemetry trigger. Existing owner policies, project tables and QR grants remain unchanged.
  3. Open website workspace → Classrooms & cloud rules. Create a class, generate an invite and approve each joining member. Students see no class projects while pending.
  4. A project owner must explicitly share a project with teachers or with all approved members. Sharing is read-only. Test using two separate accounts before classroom use.
  5. Create a hardware numeric-input cloud rule, upload fresh samples, and verify the existing event timeline. Old offline backlog is not treated as current live telemetry.
