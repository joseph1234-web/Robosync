A few things to know.

How do offline edits sync safely?

Long-press a card to reorder, or choose Arrange for size and position. Your draft is saved on the phone. Tap Queue changes. The app reuses a stable operation ID after interrupted saves. If the website changed, it keeps the draft and asks you to use the website layout or explicitly reapply your arrangement to its current widgets. Current bindings and themes are retained.

How is phone access protected?

For the retained legacy QR route, each phone generates its own random credential. The cache, credential and queued operations are encrypted with an Android Keystore key and excluded from backups. The QR contains only a five-minute invitation. Phone grants expire after 30 days. Revoke a phone from the website; offline phones learn about revocation and clear cached project data at their next online check. Offline disconnects queue server revocation.

Does synchronization run in the background?

The open app checks about every five seconds, with faster checks during approval. Android also schedules network-constrained background jobs, which battery saving, Doze or force-stop may delay. Open the app and tap Sync for an immediate refresh. Android 1.3 retains optional continuous sensor collection through a connected-device foreground service with a notification and Stop action. Force-stop, radio/power loss and Android battery policies can interrupt it. See the automatic connection guide.

Can I build and customize the APK for free?

Yes. Download the Android 1.4.1 Studio project, install SDK Platform 36 and Build-Tools 36.0.0, let Gradle sync, and build the debug APK. The source includes a detailed README, tests, build tools and the existing QR SQL. The supplied signing certificate is for development only; create your own private release key for production. Supabase uses your existing project and its applicable free-tier quotas.

Is QR setup already installed?

The live QR-result endpoint was present during a read-only check for this build. If your website reports missing QR functions, run the complete QR setup SQL once in Supabase SQL Editor. No admin key belongs in the Android app. See the connection guide.

What testing has been completed?

The new Android APK builds with SDK 36 and the existing development certificate. Signature/alignment checks and automated appearance, pin setup and retained software checks passed. The widget/pin release report records the results and limits. Hardware checks are deferred by the owner until software work is finished. Earlier phone pairing/offline/USB/direct tests were accepted by the owner. New account/mode/QR behavior needs your phone/board test. Phase4 classroom/cloud rules require the separate SQL install and two real accounts; protected camera preview needs actual camera hardware. Motor hardware remains deferred.
