Keep your current data

Install Android 1.2.0 over RoboSynct. Keep the existing app installed. Open your old dashboard first and confirm QR pairing, themes and offline cache remain.

02 / PREPARE THE ESP32

Upload the matching sketch

Open the starter's RoboSynctDirect.ino in Arduino IDE, using Espressif core 3.3.12. For a confirmed 4MB original ESP32, select Huge APP (3MB No OTA). Keep Erase All Flash disabled. Close the PC bridge before uploading.

03 / CLAIM LOCALLY

Use the physical setup code

At Serial Monitor 115200, hold BOOT after startup for three seconds, then release. Enter the private five-minute setup code in Android Settings → Connect ESP32 offline / Drive, scan for BLE and select the board.

Allow requested Nearby devices permissions. Android 8–11 also needs foreground Location permission/services for BLE discovery. A successful connection and first sample produce the actual BLE DIRECT status. Rotate the knob and test with internet off.

Local first. Cloud by choice.

Set up 2.4 GHz Wi-Fi

After enrollment, send the router/hotspot SSID and password through the encrypted BLE connection. The board reports joining, joined or failed and returns its private IP. This starter keeps network credentials in RAM. Android 1.2 can remember them encrypted on the phone and restore them after reconnecting to the enrolled board.

Alternatively, join the board's protected AP in Android Wi-Fi settings, return, and connect to 192.168.4.1. The network can work locally without internet. Android/OEM hotspot routing and wrong-password recovery need a physical test.

Append to your existing stream

Your website QR grant keeps its current scope. For local sensor uploads, separately sign in with the project owner's existing account, choose the existing hardware / Potentiometer / pot_raw stream and explicitly enable queued uploads.

Keep up to 1000 pending samples; upload in batches when internet returns. Existing readings are retained. Refresh the website and Sync your normal Android dashboard to see the confirmed samples. Movement commands never enter the cloud queue.

Drive controls have a separate hardware gate.

The native app includes a hold joystick, D-pad, 10–35% ceiling, explicit ten-second arm/lease and STOP. Firmware checks ownership, sequence and expiry, and stops after 350 ms without a valid drive heartbeat. Release, cancel, focus loss and backgrounding request stop; reconnect never resumes movement.

These controls stay disabled in the supplied sensor firmware. The source contains a reference TB6612FNG profile with a second explicit wiring-confirmation flag. Your actual driver, motor supply, pin map and physical STOP behavior must be verified before enabling it. Compile/host checks are not a motor bench test.

Recovery that keeps your project.

My board was not found or the connection failed

Check that the new Direct sketch is uploaded to an original ESP32, Bluetooth is enabled and permissions are allowed. Scan stops after ten seconds and offers retry/local Wi-Fi. Verify the one-time code and keep the board nearby. Your old USB firmware has no BLE service. A wrong code may end in an acknowledgment timeout; reopen the physical setup window and retry.

The board is already claimed, or I lost its phone key

A public board name cannot authorize takeover. To replace only its local claim, hold BOOT for eight seconds after startup. Read the new private setup code and enroll again. This stops outputs and leaves website device IDs/history intact. Manage saved direct boards removes unused or unconfirmed phone keys without resetting the website dashboard.

What happens when the app backgrounds?

Android 1.2 keeps the enrolled sensor connected through an optional connected-device foreground service and visible connection notification. Stop connection pauses automatic reconnect. Motor input stops and disarms when the Drive screen loses focus. Android force-stop, permissions, battery policy, power and range still affect collection. See the new setup and acceptance steps.

How do I roll back without uninstalling?

After Android 1.2 (code 4), use the same-signer Android 1.1 rollback (code 5). Keep the app installed. It retains workspace and encrypted direct storage while restoring previous connection behavior. A later forward update must exceed code 5.

What is verified, and what still needs testing?

Earlier Phase 1–3 phone and sensor checks were accepted by the owner. The Android 1.2 build and host tests pass; its new screen-off collection, automatic reconnect and upload behavior need handset acceptance. Motor hardware remains deferred because no driver is available.
